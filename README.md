# READIT

**Beyond the README. Follow the story.**

READIT helps developers understand what an application does and how its code makes that happen. A coding-agent skill investigates your repository, records user goals and source evidence, and produces an interactive explorer with UML use case and sequence diagrams.

The aim is to ease onboarding and address **cognitive debt**: the gap between code a team owns and behavior the team understands, including code generated by AI. This prototype makes understanding inspectable; it does not claim a measured reduction in onboarding time yet.

## Try it in 30 seconds

Requires **Node.js 22+**. No dependency installation or API key is needed for the demo.

```bash
cd readit
npm run demo
```

Open **http://127.0.0.1:4173**. Choose **Place an order**, explore successful checkout or payment decline, play the messages, and open a source reference. Stop the server with Ctrl+C.

You can also open `demo/readit.html` directly in a browser for the packaged offline experience. To rebuild it from source:

```bash
node bin/readit.js build examples/shop/readit.json --root . --out dist/readit.html
```

## What works in 0.1

- Agent Skills-compatible READIT workflow for discovering actual user goals and code flows.
- Local source inventory with Git ignore support, hashes, and entry-point hints.
- UML use case diagram: actors, system boundary, goal ellipses, include/extend dependencies.
- UML sequence diagrams: participants, lifelines, calls, returns, async arrows, self calls.
- Separate success, alternate, and error scenarios with playable message navigation.
- Source references with file/line ranges, exact snapshots, and live freshness checks.
- Visible source-backed/inferred claims, rationales, analysis scope, and limitations.
- Search, actor filter, deep links, exploration progress, dark mode, responsive layout, and reduced motion.
- Browser-local review notes exportable to your agent; JSON import and export.
- Offline HTML and editable PlantUML export. No remote diagram service.
- OpenSpec requirements, executable examples, tests, and GitHub CI.

## Use it on your own repository with Codex

From your READIT checkout:

```bash
npm link
node bin/readit.js install-skill
```

This explicitly installs the CLI and copies the skill to your Codex skills folder. It refuses to overwrite an existing READIT skill. Use `install-skill --to /path/to/skills` for another location. Restart Codex so it discovers the skill.

Open the target repository in Codex and ask:

```text
Use $readit to map this repository for developer onboarding.
Identify its main actors and user goals. Trace the implementation of the
most important use cases, including meaningful success and failure paths.
Attach exact source evidence, mark uncertainty, and generate the interactive
explorer in .readit/. Do not execute the target app or publish its source.
```

The skill guides the agent to scan, inspect source, write `.readit/readit.json`, validate it, and build `.readit/readit.html`. The explorer itself does not autonomously call an AI service.

For a manual workflow, run the following from the READIT checkout, replacing the target path:

```bash
node bin/readit.js scan /path/to/repo --out /path/to/repo/.readit/inventory.json
# Ask Codex to inspect the source and write /path/to/repo/.readit/readit.json.
node bin/readit.js validate /path/to/repo/.readit/readit.json --root /path/to/repo
node bin/readit.js build /path/to/repo/.readit/readit.json --root /path/to/repo --out /path/to/repo/.readit/readit.html
node bin/readit.js serve /path/to/repo/.readit/readit.json --root /path/to/repo
```

**Scan produces an inventory, not inferred business requirements.** The host agent supplies the semantic analysis by reading implementation and tests. No model-provider API is bundled into the CLI.

## Understand the evidence

`observed` means a model author supplied source references. `inferred` means an interpretation contains an assumption and needs a rationale. Neither label guarantees runtime correctness.

Root-based validation checks full-file SHA-256 hashes, line ranges, and supplied snippets. A changed source file makes evidence stale. Build with `--root` fails rather than silently accepting stale evidence. Serve can inspect the current referenced lines and show freshness when a reference is opened. Offline exports display recorded snapshots.

The model is versioned JSON. Its structure is in `schema/readit.schema.json`; semantic checks live in `src/model.js`. The complete demo model is in `examples/shop/readit.json`. A second model in `examples/invitations/readit.json` was generated in a separate agent trial using the portable skill.

## Continue building with OpenSpec + Codex

```bash
npm ci
npx openspec init --tools codex --no-animation
npm run spec:validate
```

The archived OpenSpec change `openspec/changes/archive/2026-10-14-implement-readit/` contains the MVP proposal, technical design, capability specs, and implementation checklist. `openspec/specs/` contains the current capability specifications. The source already implements this MVP.

For the next build, use `docs/CODEX_PROMPT.md`. A prepared, **unimplemented** change `add-framework-discovery` improves Express/NestJS entry-point discovery while keeping agent reasoning responsible for user goals. In Codex:

```text
$openspec-apply-change add-framework-discovery
```

OpenSpec uses Codex skills rather than assuming Claude slash-command names. You can also simply ask Codex to read and implement that named change. See `docs/PRODUCT_SPEC.md` for the broader product direction and `docs/ROADMAP.md` for future scope.

## Development and tests

```bash
npm ci
npm test
npm run spec:validate
npx playwright install chromium
npm run test:ui
npm run build
```

Runtime: native Node ESM + HTTP, vanilla browser JavaScript/CSS, custom SVG UML rendering. Development dependencies: OpenSpec 1.14.1 and Playwright. All versions are resolved in `package-lock.json`. CI checks models, source access boundaries, diagram export, executable fixture paths, browser interactions, OpenSpec, and build.

Repository layout:

| Path | Purpose |
|---|---|
| `bin/`, `src/` | CLI, model validation, inventory, source access, SVG/PlantUML, build, server |
| `web/` | Offline explorer UI and interactions |
| `skills/readit/` | Portable agent skill and analysis/model references |
| `examples/` | Executable shop and invitation examples with models |
| `openspec/` | Current specs and implementation changes |
| `schema/` | Structural JSON model schema |
| `test/` | Core/security/behavior tests and browser smoke checks |
| `docs/` | Product spec, Codex handoff, roadmap, demo script, AI disclosure |

## Push to your GitHub account

Create an empty repository named `readit` on GitHub. From the extracted source:

```bash
git init -b main
git add .
git commit -m "Initial READIT prototype: evidence-backed onboarding explorer"
git remote add origin https://github.com/YOUR_USERNAME/readit.git
git push -u origin main
```

If GitHub CLI is installed and authenticated, replace the last two commands with:

```bash
gh repo create readit --public --source=. --remote=origin --push
```

The project has not been published to GitHub or npm for you. `readit-dev` is a local package name, not a claim of npm availability. Update package metadata with your repository URL before publishing to npm.
